# B1-02 / B1-03: EMQX import preservation guard

Status: mitigated by disabling EMQX conversion; the requested preservation implementation remains open.

The existing conversion imports into a fresh volume and cannot establish that the target's actual authorization sources, ACL file, and non-data cluster settings survive. Restoring the image's default ACL would not preserve a customized target ACL. The check now reports a blocker and conversion refuses before accessing or modifying any target resources. This also covers direct conversion calls which bypass a check.

A complete fix needs a safe snapshot of the actual target configuration and referenced ACL files, a defined merge policy for each data root, and verification against the effective configuration after import. The authorization probe must be based on the actual target policy; a blanket cross-user denial is not valid for every customized ACL. Exercise successful and failing cases using a disposable EMQX instance before removing the guard. Review B1-06's untrusted broker execution concern alongside that work.

Validation: `PYTHONPATH=backup-engine python3 -m unittest discover -s tests/backup -p test_ha_emqx_preservation_guard.py -v` (2 passed). Existing successful EMQX conversion tests are intentionally incompatible with this temporary guard and were not represented as passing. No production services or volumes were changed.
