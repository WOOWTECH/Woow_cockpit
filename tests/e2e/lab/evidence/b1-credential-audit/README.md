## Producer and consumer inventory

* Omnigent 0.21.0 package `rootfs/usr/local/bin/omnigent-runner-login` requests `issue_refresh` at `/auth/login` and hands response `token` and optional `refresh_token` to `omnigent.cli_auth.store_token`. The latter stores them per server in `auth_tokens.json`. A missing refresh grant is accepted by that upstream program, but must fail a refresh-continuity acceptance claim.
* Omnigent 0.21.0 `omnigent/cli_auth.py` `refresh_stored_token` sends the stored grant to `/oauth/token`. A successful response provides `access_token`; a missing, null, empty or invalid replacement `refresh_token` causes upstream to retain the existing grant. It then persists the new pair. Any capture system must retain all generations, not just the first and last file snapshot. This audit helper intentionally rejects a present but unusable replacement, a stricter coverage rule.
* The prerequisites branch's guarded `ha_import_b1_e2e.py` contains probe logins, runner token file reads, and the `scenario_leaks` consumer. That file is absent from the specified mainline, so it has not been silently imported or treated as an active mainline consumer. The separate prerequisites worktree has uncommitted, concurrently changing registration work; this audit does not modify or duplicate it.
* The guarded driver also contains Hermes cookie-jar logins, EMQX dashboard logins, and an Omnigent negative login; a successful response to an expected-failure login can also issue material. These paths require their own producer-bound capture and missing-response policy before any blanket coverage claim. No Hermes review or service operation was repeated. Headscale and EMQX were not operated.
* The copied runner grant and live runner can produce credentials independently of a verifier's probe logins. No reliable complete runner event stream has been connected to the acceptance driver's registry or leak scan here. In particular, an `end` event in the offline helper is an assertion by the caller, not independent proof of capture completeness.
