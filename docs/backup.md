# 備份與還原（管理者指南）

Cockpit「備份與還原」頁為 rootless Podman Quadlet 應用建立加密備份。備份預設保存在這台設備，可下載成一個 `.woowbackup` 檔，再上傳到同一台或另一台相容設備還原。原位還原前一定先建立「還原前自動備份」，還原失敗時自動回復。作業在背景執行，關閉瀏覽器也會繼續。

> **現況（第一階段）：** 功能已在兩台隔離的實驗室設備（Ubuntu 24.04、Cockpit 362、Podman 4.9.3、x86_64）以示範應用 `woowbk-demo` 完成端到端驗證。本文的時間與大小數據都來自該環境與少量測試資料，只供參考。**正式應用尚未啟用**，見下一節。

工程規格見 [CONTRACT.md](backup/CONTRACT.md)；應用如何加入備份見 [app-catalog.md](backup/app-catalog.md)；安裝、維護與測試見 [deployment.md](deployment.md)、[operations.md](operations.md)、[testing.md](testing.md)。

## 目前可備份的應用

頁面只列出設備上裝有「受信任應用目錄項目」（catalog entry，`/etc/woowtech-cockpit/backup/apps/<應用 ID>.json`）的應用。目錄項目明確列出應用的擁有者帳號、服務、資料庫、資料卷、密鑰與設定檔；頁面不會自動掃描或備份其他容器。

- 一般安裝（`manage.py install`）不含任何目錄項目，頁面會顯示「尚未設定可備份的應用」。
- 示範應用 `woowbk-demo` 只能用 `--backup-demo-catalog` 安裝到實驗室設備，**不可用於客戶設備**。
- **正式應用（LiteLLM、n8n、Odoo 等）尚未啟用。** 每個應用都要由該應用的套件提供目錄項目，經過審查，並在實驗室完成同機還原、跨設備還原與失敗回復演練後，才會加入。盤點與接入順序見 [production-onboarding.md](backup/production-onboarding.md)。

此階段不包含：排程與保留策略、NAS 或雲端目的地、root（系統層級）Quadlet 應用、多節點應用、整機或裸機還原。

## 開啟頁面與權限

從 Cockpit 側欄開啟「備份與還原」。此頁會讀取所有應用的資料與加密金鑰，所以**只有取得管理員存取權限後才能使用**。未取得權限時只顯示「需要管理員權限」，不載入資料、不執行任何動作；在 Cockpit 頂端開啟「管理員存取權限」後，頁面會自動重新載入。

頁面有五個分頁：「總覽」「備份列表」「從檔案還原」「加密金鑰」「活動紀錄」。「總覽」顯示可備份的應用與狀態（執行中、已停止、部分執行、未部署、無法讀取）、最近的備份、本機儲存空間與金鑰狀態。服務都在執行、但快速健康檢查沒有通過的應用，也會標為「無法讀取」並列出原因。目錄項目有問題而被略過時，總覽上方會出現「備份設定提示」。

**第一次使用請先到「加密金鑰」建立金鑰並保存緊急金鑰**，否則無法建立備份。

## 備份包含什麼

每份備份只包含目錄項目列出的內容：

| 項目 | 內容與取得方式 |
| --- | --- |
| PostgreSQL 資料庫 | 目錄列出的每個資料庫，以 `pg_dump` 自訂格式匯出；匯出後完整讀取一次，確認可以還原。只包含該資料庫本身，不含角色等叢集層級設定 |
| 資料卷 | 目錄列出的具名 Podman 資料卷（`podman volume export`） |
| 密鑰 | 目錄列出的 Podman secrets 原始內容（例如資料庫密碼、應用金鑰） |
| 設定檔 | 目錄列出、位於擁有者 `~/.config/<應用 ID>/` 或 `~/.local/share/<應用 ID>/` 之下的單一檔案及其權限 |
| Quadlet 定義 | 應用 Quadlet 檔的副本，僅供紀錄；還原時不會安裝備份檔中的 Quadlet（見「還原以這台設備的設定為準」） |
| 容器映像（選用） | 勾選「包含容器映像」時，以 `podman save` 匯出應用使用的映像 |
| 資料核對快照 | 目錄設定了核對端點時，備份前讀取的業務摘要（例如筆數、內容雜湊），還原後用來比對 |
| 備份資訊 | 建立時間、來源主機名稱與 CPU 架構、作業系統、Podman 與備份元件版本、備份時暫停寫入的秒數、每個項目的大小與 SHA-256 |

不包含目錄未列出的任何東西，例如主機資料夾掛載（bind mount）、其他帳號的資料、作業系統與 Cockpit 設定，以及加密金鑰本身。資料庫執行個體中若還有目錄未宣告的資料庫或角色，作業紀錄會註明它們不在備份中。

一份備份就是一個檔案：檔頭之後是以 [age](https://github.com/FiloSottile/age)（X25519）加密的 zstd 壓縮 tar。下載檔名為 `woowtech-backup-<主機名稱>-<YYYYMMDD-HHMMSS>.woowbackup`，時間為 UTC（較早版本建立的檔名沒有秒數）。

## 備份如何保持資料一致

1. **先檢查空間。** 保存位置的可用空間須至少為預估資料量的 2.2 倍再加 512 MiB。不足時，作業在暫停任何服務之前就停止（`insufficient-space`）。
2. **讀取資料核對快照**（有設定時）。
3. **短暫暫停寫入服務。** 只停止目錄列為寫入服務（`writer_units`）且正在執行的服務；資料庫保持執行，以便匯出。
4. **匯出。** `pg_dump` 匯出資料庫並完整讀取檢查，接著匯出資料卷、密鑰、設定檔與 Quadlet 檔。
5. **立即恢復。** 無論匯出成功或失敗，都會重新啟動剛才暫停的服務（每個服務最多試兩次）。匯出失敗、且資料庫在過程中停止時，也會嘗試重新啟動資料庫，再重新啟動寫入服務讓它們重新連線。
6. **再次確認核對快照**（有設定時）。服務恢復後再讀一次；與暫停前不同時（例如仍有寫入進行中，或設定在服務重新啟動時才生效），這份備份不保存快照，日後還原時略過資料比對，作業紀錄會說明。
7. **映像在服務恢復後才匯出**，不會延長暫停時間。映像若在備份期間被更換，備份失敗並要求重做。
8. **加密、驗證後才列出。** 備份檔先寫在私有暫存區，用這台設備的金鑰完整解密並逐項核對大小與 SHA-256，通過後才移到保存位置、出現在列表。未通過驗證的備份不會被列出。

暫停時間會記錄在備份中，備份詳情顯示為「備份時暫停應用寫入 N 秒」。選擇多個應用時逐一處理，每個應用只在自己的匯出期間暫停。實驗室示範應用的含映像備份（142 MB）中，寫入暫停 2–3 秒，健康檢查端點最長 1.5–3.3 秒無法回應；實際時間取決於資料量。

應用在備份前沒有完整執行時，備份後不等待健康檢查；沒有任何寫入服務需要暫停時，暫停時間記為 0。

## 備份保存在哪裡

備份保存在這台設備的 `/var/lib/woowtech-backup/archives/`（只有 root 可存取）：每份備份是一個 `<備份 ID>.woowbackup` 檔，加上一個列表用的 `.json` 索引。「總覽」的「本機儲存空間」顯示保存位置、可用空間與備份佔用量。其他執行資料的位置見 [operations.md](operations.md)。

**本機備份與應用資料通常在同一顆磁碟，無法防範磁碟故障或設備遺失。** 重要的備份請下載保存到其他位置。

| 列表中的類型 | 來源 |
| --- | --- |
| 手動 | 從「建立備份」建立 |
| 還原前自動 | 原位還原前由系統建立。每個應用保留最近 3 份，較舊的在之後的原位還原成功後自動刪除；失敗或中斷的還原仍需要的還原前備份不會被自動刪除 |
| 上傳 | 從「從檔案還原」上傳的檔案 |

手動與上傳的備份不會自動刪除，請定期清理。

## 建立備份

1. 按「建立備份」。
2. 勾選要備份的應用，可一次選多個。尚未部署或無法讀取狀態的應用不能選。
3. 決定是否勾選「包含容器映像」（見下方）。
4. 可填寫備註（最多 200 字，不可包含換行或 Tab）。
5. 按「開始備份」。頁面會轉到作業進度；可以關閉瀏覽器，稍後到「活動紀錄」查看。

建立備份需要：這台設備已建立加密金鑰、應用已部署且資料庫服務正在執行、沒有其他作業進行中。

**何時包含容器映像：** 要還原到無法連網、或取不到相同映像的設備時必須包含。以 `localhost/` 開頭的本機建置映像無法從映像庫下載，要在其他設備還原就一定要包含。包含映像會讓檔案明顯變大：實驗室示範應用含兩個映像約 142 MB，不含映像約 145–183 KB。

## 檢視、驗證、下載與刪除

在「備份列表」或備份詳情可以：

- **檢視內容**：解密備份的內容清單，列出應用、資料庫、資料卷、映像是否包含、密鑰與設定檔數量，以及與這台設備的相容性檢查。不會變更任何資料。
- **驗證**：在背景完整解密整個檔案，逐項核對大小與 SHA-256，結果顯示為「已驗證」或「驗證未通過」。還原時本來就會先完整驗證；單獨驗證適合定期確認保存的舊備份或剛上傳的備份是否完好。驗證未通過的備份請勿用來還原。
- **下載**：瀏覽器經由 Cockpit 的加密連線下載單一 `.woowbackup` 檔。
- **刪除**：確認後刪除，無法復原；需要保留請先下載。刪除「還原前自動」備份後，就無法再用它回到那次還原之前的狀態。正被作業使用的備份不能刪除；還原作業進行中時，任何「還原前自動」備份都不能刪除（失敗時可能需要它自動回復）。

下載的檔案已加密，但內含資料庫、檔案與應用密鑰。請和緊急金鑰分開存放，見「安全須知」。

## 在同一台設備還原（原位還原）

在「備份列表」選擇備份的「還原」，依序完成：

1. **金鑰**：只有這台設備沒有該備份的金鑰時，才會要求輸入緊急金鑰。
2. **預檢**：顯示整體檢查與每個應用的檢查結果。選擇要還原的應用；未通過檢查的應用無法選擇。預檢不會變更任何資料。
3. **確認**：頁面列出受影響的應用、停機影響與還原前備份的做法。勾選「我了解還原會停止並覆寫上列 N 個應用的資料」後按「開始還原」。
4. **進度與結果**：結果頁列出健康檢查，以及「備份時」與「還原後」的資料核對表（資料一致、資料不一致或未比對）。

還原作業依序執行：

1. 解密整個備份檔到私有暫存區，逐項核對大小與 SHA-256。
2. 相容性檢查（內容同預檢）。
3. **建立還原前備份**：為受影響的應用建立並驗證一份「還原前自動」備份（不含映像）。建立失敗時作業停止，應用資料不做任何變更。資料庫服務沒有執行時，會先嘗試啟動它。接著確認保存位置的空間足以在失敗時解開這份還原前備份；不足時作業停止，不做任何變更。
4. 變更前的檢查與準備（應用仍在執行）：完整檢查備份中的資料卷與映像封存；資料庫執行個體中若有目錄未宣告的資料庫，拒絕原位還原（重建資料卷會讓它們遺失）。接著載入備份中的映像，或從映像庫下載缺少的映像；若映像在備份後更新過，映像標籤會指回備份時的版本（備份包含該映像，或這台設備仍保留該版本時）。這一步失敗時，映像標籤會改回還原前的版本。
5. 依相反順序停止應用的服務，並暫時停用資料庫以外的服務，還原完成前不會被自動啟動（包括開機時）。
6. 還原資料：重建密鑰、寫入設定檔、刪除並重建資料卷，刪除資料庫的資料卷。
7. 啟動：先啟動資料庫，讓它重新初始化後以單一交易匯入資料，再恢復被暫時停用的服務，依目錄順序啟動。
8. 健康檢查與資料核對。

第 5 步之前失敗時，應用資料沒有被變更。**第 5 步開始後的任何失敗都會自動回復：** 系統用剛建立的還原前備份把應用回到還原前的狀態，作業顯示「已自動回復」。自動回復不會從映像庫下載映像，需要的映像版本必須仍在這台設備上。若自動回復也沒有完成，作業顯示「失敗」與「需人工處理」，並列出還原前備份 ID，可用它再次還原。

注意事項：

- 還原後，應用回到備份當時的資料；備份之後才寫入的資料會被覆寫（仍保留在這次的還原前備份中）。
- 原位還原會以備份中的單一資料庫重建整個資料庫資料卷。資料庫執行個體中的其他資料庫會讓還原被拒絕；資料庫角色與權限設定不會保留，預檢會列出它們。
- 原位還原需要這台設備已建立加密金鑰，用來建立還原前備份。
- 實驗室示範應用的原位還原（含建立還原前備份）共 24–31 秒，其中應用無法使用 9.4–11.3 秒。實際時間取決於資料量與映像。
- 還原一份「還原前自動」備份時，若無法再建立新的還原前備份（例如應用因先前的還原中斷而無法執行），作業會直接還原，失敗時無法自動回復；作業紀錄會寫明這點。

## 在另一台設備還原

### 目標設備須符合

| 條件 | 說明 |
| --- | --- |
| CPU 架構相同 | 來源與目標架構不同時預檢會提示；備份內含其他架構的映像時預檢失敗。實驗室只驗證過 x86_64 |
| 系統版本 | 已驗證的組合為 Ubuntu 24.04、Cockpit 362、Podman 4.9（4.9.3）；其他組合未驗證 |
| 已安裝本專案 | 含「備份與還原」套件，以及 age 與 zstd（`bootstrap-ubuntu.sh` 會安裝），見 [deployment.md](deployment.md) |
| 已安裝該應用的目錄項目 | 應用 ID 與來源相同。應用尚未部署時，目錄項目還要提供部署範本。**還原以這台設備的目錄項目為準** |
| 應用擁有者帳號 | 這台設備目錄項目指定的帳號必須存在；UID 可以與來源不同（實驗室由 UID 1001 還原到 1007）。帳號要能執行 rootless Podman（已設定 subuid／subgid），並已啟用 linger，使用者服務管理器正在執行 |
| 映像取得得到 | 備份包含映像、這台設備已有相同映像，或可從映像庫下載。`localhost/` 映像必須包含在備份中 |
| PostgreSQL 版本 | 10 以上；備份的 PostgreSQL 主版本不可高於這台設備資料庫映像的主版本 |
| 可用空間 | 保存位置：上傳需要檔案大小再加 512 MiB，解開備份需要備份內容大小再加 512 MiB；應用擁有者家目錄所在磁碟：約為該應用在備份中的資料量（含映像）的 2 倍再加 512 MiB |
| 金鑰 | 建立備份那台設備的緊急金鑰，或已匯入這台設備的同一把金鑰 |

### 步驟

1. 在來源設備下載備份檔。
2. 在目標設備開啟「從檔案還原」，拖放或選擇 `.woowbackup` 檔並開始上傳。上傳只把檔案放進私有暫存區，不會變更任何應用，過程中可以取消。完成後這份備份會以「上傳」類型留在「備份列表」，之後可再還原或刪除。
3. 頁面要求金鑰時，貼上以 `AGE-SECRET-KEY-1` 開頭的整行金鑰，或讀取緊急金鑰 `.txt` 檔（檔案只在瀏覽器讀取，不會上傳）。勾選「保存此金鑰到這台設備」，日後同一把金鑰的備份就不必再輸入；金鑰要先確認能解開這份備份才會保存，錯誤的金鑰不會被存下。不勾選時，金鑰只交給這次作業使用，作業結束即刪除。
4. 預檢、確認、進度與結果同原位還原。

### 全新部署或原位還原

| 目標設備狀況 | 還原方式 |
| --- | --- |
| 沒有該應用的任何 Quadlet 檔 | **全新部署**：用這台設備上受信任的範本建立服務，再還原密鑰、設定檔、資料卷與資料庫。這台設備已有同名的資料卷、密鑰或設定檔（例如先前移除應用時留下的）時預檢失敗，請先移除；這可避免還原失敗時把它們一併刪除 |
| 該應用的 Quadlet 檔都在 | **原位還原**：同上一節，先建立還原前備份 |
| 只有部分 Quadlet 檔，或其中有符號連結 | 無法判斷，預檢失敗；請先修復部署 |

全新部署失敗時，系統會移除這次新建立的 Quadlet 檔、服務、資料卷、密鑰與設定檔，作業顯示「已自動回復」。

設定檔會原樣寫入。若其中含有來源設備特有的值（例如 IP、網域），還原後需自行確認。

實驗室已驗證：dev-a 的備份經頁面下載、上傳到 dev-b（應用擁有者 UID 不同、應用未部署），全新部署後資料摘要與備份時相同，應用也能寫入新資料。

### 還原以這台設備的設定為準

備份檔只提供資料內容。要寫入哪些密鑰、設定檔路徑、資料卷、資料庫與服務，一律由**目標設備**的目錄項目決定：

- 備份中有、但這台設備目錄未列出的項目，會被略過並在預檢提示。
- 這台設備目錄要求、但備份缺少的項目，會讓預檢失敗。
- 備份檔中的 Quadlet 檔從不安裝；全新部署只用目標設備上 root 擁有的範本。
- 備份檔不能攜帶任何程式；如何備份、還原由設備上安裝的備份元件決定。

## 加密金鑰與緊急金鑰

### 設備金鑰

每台設備有一把備份金鑰（age X25519），在這台設備建立的備份都用它加密。在「加密金鑰」按「建立加密金鑰」建立；金鑰保存在 `/etc/woowtech-cockpit/backup/keys/`，只有 root 可讀取。金鑰以 `XXXX-XXXX-XXXX-XXXX` 格式的金鑰 ID 識別，備份詳情會顯示該備份是用哪一把金鑰加密。

### 緊急金鑰

建立金鑰後，頁面顯示金鑰 ID 與完整金鑰，並提供「下載緊急金鑰」與「複製金鑰」。緊急金鑰檔名為 `woowtech-backup-key-<主機名稱>-<金鑰 ID>.txt`，內含金鑰 ID、建立時間、建立設備、以 `AGE-SECRET-KEY-1` 開頭的金鑰，以及在其他設備還原的步驟。

保存後勾選「我已將緊急金鑰保存到這台設備以外的安全位置」，再按「完成」。確認之前，頁面會持續提醒，也可以再按「顯示並下載緊急金鑰」。確認後頁面不再顯示金鑰內容；如需另一份，可在「加密金鑰」按「重新下載緊急金鑰」，下載的檔案同樣含有完整金鑰。

**遺失緊急金鑰的後果：** 這台設備故障或重新安裝時，設備上的金鑰會一起消失。沒有緊急金鑰，用它加密的備份將**永遠無法還原**，任何人（包括 WOOWTECH）都無法找回或重設。

請保存在密碼管理器、加密隨身碟，或列印後上鎖保管。不要用電子郵件、聊天訊息或公開雲端分享傳送，也不要和備份檔放在同一處：同時取得金鑰與備份檔的人，可以讀取備份中的資料庫、檔案與應用密鑰。

### 匯入其他設備的金鑰

這台設備需要經常還原另一台設備的備份時，可在「加密金鑰」的「匯入其他設備的金鑰」貼上金鑰或讀取緊急金鑰檔，或在還原時勾選「保存此金鑰到這台設備」。匯入的金鑰只用於解密，不會用來加密這台設備的新備份。

目前不提供更換（輪替）設備金鑰，也不能從頁面移除已匯入的金鑰。

## 作業與進度

備份、還原與驗證都以背景作業執行（systemd 暫時單元 `woowtech-backup-<作業 ID>.service`）。關閉瀏覽器或連線中斷都不影響作業；重新開啟頁面會回到進行中的作業。「活動紀錄」列出最近 50 筆作業，每筆可查看階段、進度與最近 200 行紀錄；紀錄不含金鑰與密鑰內容。

**同一時間只能有一個作業。** 已有作業進行中時，新的要求會被拒絕（`busy`），頁面會連到進行中的作業。重複送出同一個要求（例如逾時後再按一次）會回到同一個作業，不會重複執行。

### 階段

| 作業 | 階段 |
| --- | --- |
| 備份 | 準備 → 檢查空間與應用 → 暫停應用寫入 → 匯出資料庫 → 匯出資料卷與設定 → 恢復應用 → 加密封裝 → 驗證備份 |
| 還原 | 準備 → 解密並驗證檔案 → 相容性檢查 → 建立還原前備份 → 停止應用 → 還原資料 → 啟動應用 → 健康與資料核對；失敗時加上「自動回復」 |
| 驗證 | 準備 → 解密並驗證檔案 → 核對結果 |

全新部署沒有還原前備份，該階段顯示「略過」。

### 狀態

| 狀態 | 意思 |
| --- | --- |
| 等待開始 | 已排入，尚未開始 |
| 執行中 | 正在執行 |
| 已完成 | 成功。還原時代表健康檢查通過，且資料核對一致或沒有可比對的快照 |
| 失敗 | 沒有完成。備份失敗不會留下備份檔；還原若在變更資料前失敗，應用未被變更。顯示「需人工處理」時，代表自動回復也沒有完成 |
| 已自動回復 | 還原在開始變更後失敗，系統已用還原前備份（全新部署則移除新建立的項目）回到還原前的狀態；錯誤訊息說明失敗原因 |
| 已中斷 | 作業程序意外結束（例如被強制終止、斷電、重新開機），見下方 |
| 已取消 | 依要求在安全的檢查點停止：備份不會列出、寫入服務已恢復；還原在變更任何資料前就停止 |

### 取消

只能在不會留下不完整狀態的階段取消：

- **備份**：「暫停應用寫入」之前，以及「加密封裝」「驗證備份」期間（未完成的備份檔會被丟棄，服務在這之前已恢復）。從暫停寫入到恢復應用之間不能取消。
- **還原**：只能在「建立還原前備份」之前取消。
- **驗證**：隨時可以取消。

不能取消時頁面顯示「目前階段無法取消」（`not-cancellable`），作業會繼續到完成或自動回復。取消要求一旦被接受，作業一定在進入下一個不能取消的階段之前停止，不會接受取消之後又暫停寫入或開始變更資料。

### 已中斷的作業

作業程序被強制終止、斷電或系統重新開機時，作業無法自行收尾。之後開啟頁面（讀取狀態、作業或活動紀錄）時，系統會把它標為「已中斷」，並且：

- 清除它的暫存資料與暫時金鑰；
- 重新啟動備份時被暫停、還沒恢復的寫入服務；
- **不會自動重做**任何作業。

系統關機或重新開機時，若還原已開始變更資料，作業不會嘗試自動回復，而是結束為「已中斷」，開機後依下方方式處理。

處理方式：

- **備份中斷**：到「總覽」確認應用已恢復執行，再重新建立備份。中斷的備份不會被列出。
- **原位還原中斷**：若已建立還原前備份，結果頁會列出它並提供「使用還原前備份還原」，可把應用回到這次還原開始前的狀態。還原中被暫時停用的服務會保持停用，「總覽」會提示該服務已被暫時停用、先前的還原沒有完成，避免應用在只還原一半的資料上啟動；用還原前備份再次還原完成後即恢復。若在建立還原前備份之前就中斷，應用資料應未被變更；確認應用狀態後再決定是否重新還原。
- **全新部署中斷**：系統判定中斷時會清除未完成的部署（Quadlet 檔、資料卷、密鑰與設定檔），結果訊息會說明是否完整清除；清除完成後可再次還原同一份備份，未能完整清除時需人工處理。設備實測：驗證結果待回歸測試更新。
- 不確定應用狀態時，先到「服務管理」檢查服務，或聯絡系統管理員。主機端的處理方式見 [operations.md](operations.md)。

實驗室已驗證：在「還原資料」階段強制終止還原作業後，作業顯示「已中斷」與還原前備份 ID，用還原前備份還原後，資料與中斷前相同。設備重新開機造成的中斷：驗證結果待回歸測試更新。

## 錯誤代碼

頁面顯示中文訊息；代碼供回報問題時使用。

| 代碼 | 意思與常見原因 | 處理方式 |
| --- | --- | --- |
| `invalid-request` | 輸入或請求不正確，例如金鑰不是以 `AGE-SECRET-KEY-1` 開頭的完整一行、備註含換行、上傳檔案大小與宣告不符（上傳未完成）、這台設備已有同 ID 但內容不同的備份；應用目錄項目格式錯誤也使用此代碼 | 依訊息修正後重試；金鑰請完整複製一行；上傳不完整請重新上傳；目錄項目錯誤請交給應用套件維護者（見 [app-catalog.md](backup/app-catalog.md)） |
| `not-found` | 找不到備份、作業或上傳工作（可能已刪除，或未完成的上傳超過 24 小時已被清除）；或找不到應用的設定檔 | 重新整理列表；重新上傳；確認應用部署完整 |
| `busy` | 已有作業進行中；已有 4 個尚未完成的上傳；要刪除的備份正被作業使用，或在還原作業進行中刪除還原前備份 | 等進行中的作業或上傳完成後再試，頁面會連到進行中的作業 |
| `key-required` | 這台設備沒有加密這份備份的金鑰 | 輸入建立備份那台設備的緊急金鑰，或先匯入金鑰 |
| `wrong-key` | 提供的金鑰不是加密這份備份的那一把，或金鑰無效 | 核對備份顯示的金鑰 ID 與緊急金鑰檔上的金鑰 ID 是否相同 |

| `not-a-backup` | 檔案不是 WOOWTECH 備份檔 | 確認選擇的是 `.woowbackup` 檔，且下載完整 |
| `unsupported-format` | 備份檔格式版本較新，或加密、壓縮方式不受支援 | 將這台設備的備份元件更新到不舊於建立備份的版本 |
| `corrupt-archive` | 檔案損毀或遭修改，例如被截斷、位元錯誤、內容與清單不符 | 不要用它還原；改用另一份備份，或從原設備重新下載 |

| `limit-exceeded` | 超出安全限制：超過 4000 個項目、內容清單超過 1 MiB、總量超過 2 TiB；設定檔、部署範本、目錄項目過大；或指令輸出超過上限 | 本版本無法處理此檔案或設定；設定過大時請應用套件維護者調整 |

| `incompatible` | 相容性檢查未通過：缺少映像、PostgreSQL 主版本較高或早於 10、映像架構不同、Quadlet 檔不完整、全新部署時已有同名資料卷／密鑰／設定檔、原位還原時資料庫執行個體有未宣告的資料庫、備份缺少這台設備設定需要的項目、缺少部署範本、備份由較新版本的轉接器建立；自動回復需要的映像版本已不在設備上 | 依預檢逐項處理後按「重新檢查」；預檢與還原開始前的檢查未通過時，沒有任何變更 |
| `app-not-in-catalog` | 這台設備沒有該應用的目錄項目 | 先安裝經審查的目錄項目；正式應用目前尚未提供 |
| `owner-missing` | 應用擁有者帳號不存在、家目錄設定不正確，或無法以該帳號執行命令 | 建立與目錄項目同名的帳號（UID 可不同），設定 rootless Podman 與 linger |
| `not-deployed` | 應用尚未部署在這台設備（無法備份），或找不到目錄列出的資料卷 | 確認應用已部署並啟動，資料卷名稱與目錄項目一致 |
| `permission-denied` | 沒有管理員權限；或目錄項目、部署範本與其資料夾的擁有者或權限不安全（不是 root 擁有、可被其他帳號寫入、符號連結）；或擁有者家目錄中的路徑含符號連結 | 在 Cockpit 開啟管理員存取權限；檔案權限由 root 修正（root 擁有，檔案 0644、資料夾 0755） |
| `not-cancellable` | 作業已進入不能中斷的階段 | 等作業結束；還原失敗時會自動回復 |
| `job-failed` | 作業步驟失敗：服務無法停止或啟動、資料庫匯出或匯入失敗、健康檢查未通過、資料核對不一致、無法建立還原前備份等；「已中斷」的作業也記錄此代碼 | 查看結果訊息與作業紀錄最後幾行；到「服務管理」檢查服務；出現「需人工處理」時，用列出的還原前備份再次還原 |
| `internal-error` | 未預期的錯誤，例如備份元件安裝不完整或權限不安全、缺少 age 或 zstd、無法啟動背景作業 | 用 `manage.py verify` 檢查、`install` 修復，確認 age 與 zstd 已安裝；查看系統日誌（見 [operations.md](operations.md)） |

頁面另有幾種非代碼狀態：「找不到備份管理程式」表示這台主機未安裝或未完整安裝備份元件；「管理連線已中斷」時按「重新連線」，已送出的背景作業會繼續、不會重送；「操作回應逾時」時先重新整理確認狀態，再決定是否重試。

## 安全須知

- **只有管理員可以使用。** 頁面以 Cockpit 管理員權限呼叫 root helper；helper 在非 root 身分下拒絕執行。任何能在 Cockpit 取得管理員權限的帳號，都能檢視、下載、還原與刪除所有應用的備份；管理員之間沒有分權。
- **備份含有密鑰。** 資料庫、檔案、Podman secrets（例如資料庫密碼與應用金鑰）與設定檔都在備份中。下載的檔案雖已加密，仍請像保管密碼一樣保管，並與緊急金鑰分開存放。
- **本機加密不防 root。** 本機備份與設備金鑰在同一台設備上，具有 root 權限的人可以解密本機備份。加密主要保護下載到其他位置的檔案。
- **作業期間有明文暫存（殘留風險）。** 備份與還原過程中，資料庫匯出、資料卷內容與密鑰會以未加密形式暫存在 `/var/lib/woowtech-backup/staging/<作業 ID>/`（只有 root 可存取），作業結束或被判定中斷時刪除。刪除後的資料區塊可能留在磁碟上直到被覆寫，系統不做安全抹除；需要防範磁碟被取出讀取時，請使用整碟加密。
- **金鑰只經標準輸入傳遞。** 輸入的金鑰經 Cockpit 加密連線送到 helper 的標準輸入，不會出現在網址、命令列參數、作業紀錄或日誌。只供單次作業使用的暫時金鑰檔放在 `/run/woowtech-backup/`（記憶體檔案系統，0600），作業結束即刪除。實驗室檢查兩台設備的作業紀錄、日誌、索引與 journal，沒有發現應用密鑰或金鑰。
- **只還原可信來源的備份。** 上傳的檔案在完整驗證前一律視為不可信：檔頭、加密認證、每個項目的大小與雜湊都要通過，路徑穿越、連結、多出或缺少的項目都會被拒絕；備份中的資料卷與映像封存在交給 Podman 之前，也會先完整檢查並重新產生。但能解密只證明檔案在加密後沒有被修改，不能證明它來自哪一台設備；還原的資料庫內容與設定檔會被應用直接使用。請只還原自己保管的備份檔。

## 已知限制

- **一次只能執行一個作業。** 備份、還原與驗證互斥；同時進行中的上傳最多 4 個。
- **沒有排程、保留策略、NAS 或雲端目的地。** 手動與上傳的備份不會自動刪除；只有還原前自動備份每個應用保留 3 份。
- **本機備份不防磁碟故障。** 備份與應用資料通常在同一顆磁碟，請下載保存到其他位置。
- **上傳速度。** 實驗室經瀏覽器上傳 142 MB 約需 15.8–18.1 秒（約 9 MB/s，含上傳後的檢查）；下載約 5.8–7.3 秒。多 GB 的檔案上傳會很慢，尚未實測多 GB 備份。較大傳輸視窗的評估：驗證結果待回歸測試更新。
- **未套用的設定變更。** 備份會重新啟動寫入服務。若應用的設定檔已修改、但尚未重新啟動套用，這次重新啟動會讓新設定生效；如果因此改變了核對值，這份備份不會保存資料核對快照，日後還原時無法比對資料。請先套用（重新啟動）或撤回設定修改，再備份或還原。
- **PostgreSQL。** 支援 PostgreSQL 10 以上；備份的主版本不可高於目標設備的資料庫映像。只備份目錄列出的資料庫，不含角色等叢集層級設定；匯入時所有物件改由目錄指定的資料庫帳號擁有，不還原原本的擁有者與授權。資料庫執行個體中有目錄未宣告的資料庫時，不能原位還原。實驗室只驗證過 PostgreSQL 16 還原到 16。
- **支援的資料形態有限。** 只支援具名資料卷（還原時以預設選項重建）、應用自己設定目錄下的單一設定檔（每個最大 16 MiB）、Podman secrets（每個小於 512,000 bytes）。主機資料夾掛載、整個設定資料夾、資料放在主機資料夾的資料庫都尚未支援。
- **還原會停機並覆寫資料。** 還原期間應用停止服務；原位還原會覆寫備份之後寫入的資料（保留在還原前備份中）。
- **跨設備範圍。** 只驗證相同架構（x86_64）與上述系統版本；不同 CPU 架構未測。
- **金鑰管理。** 不能輪替設備金鑰，也不能從頁面移除已匯入的金鑰。
- **尚未實測的情境。** 多 GB 備份與超過 8 GiB 的單一項目、不同 CPU 架構尚未實測。惡意封存檔、空間不足、資料庫匯出失敗、備份作業被強制終止、設備重新開機與安裝器回退的設備實測：驗證結果待回歸測試更新（整合輪時前三項只有單元測試）。
- **正式應用尚未啟用。** 每個應用需先完成目錄項目審查與實驗室演練。

## 實驗室驗證紀錄

2026-11-13 整合輪在兩台實驗室設備（Cockpit 362-1~bpo24.04.1、Podman 4.9.3、age 1.1.1、zstd 1.5.5）以示範應用完成以下情境，下載與上傳都經過設備上真正的 Cockpit 連線：

| 情境 | 結果 |
| --- | --- |
| 同機：建立金鑰與緊急金鑰、含映像備份、變更資料、原位還原 | 資料摘要等於備份時，還原前備份列出 |
| 跨設備：A 下載 → B 上傳 → 緊急金鑰 → 全新部署（UID 1001 → 1007） | 健康、資料摘要相同、可寫入新資料；未留下匯入的金鑰 |
| 錯誤金鑰、非備份檔、新版格式、截斷、翻轉一個位元組 | 都被拒絕，沒有變更任何資料，暫存區清空 |
| 不含映像的備份還原到沒有該映像的設備 | 預檢失敗，沒有建立任何東西 |
| 還原在開始變更後失敗 | 自動回復，資料等於還原前 |
| 還原作業被強制終止 | 「已中斷」與指引；用還原前備份還原後資料等於中斷前 |
| 取消 | 暫停寫入期間取消被拒絕；封裝期間取消後沒有列出備份、殘檔清除、服務執行中 |
| 重複或同時送出要求 | 同一要求回到同一作業；其他要求得到 `busy` |
| 作業中關閉瀏覽器 | 作業完成，重新開啟後頁面回到作業 |
| 非管理員 | 顯示需要管理員權限，不執行任何動作 |
| 洩漏檢查 | 作業紀錄、日誌、索引與 journal 沒有應用密鑰或金鑰 |

實測時間（142 MB 含映像備份，設備限制 768 MiB 記憶體、1.5 CPU）：

| 項目 | 數值 |
| --- | --- |
| 含映像備份 | 24–61 秒（`podman save` 佔 13–33 秒）；寫入暫停 2–3 秒 |
| 不含映像備份 | 約 5 秒，145–183 KB |
| 原位還原（含還原前備份） | 24–31 秒；應用無法使用 9.4–11.3 秒 |
| 全新部署還原 | 12–17 秒（已有資料庫映像）；28–64 秒（兩個映像都要載入） |
| 失敗後自動回復 | 約 23 秒 |
| 瀏覽器下載／上傳 142 MB | 5.8–7.3 秒／15.8–18.1 秒 |

強化測試（惡意封存檔、空間不足、資料庫匯出失敗、各階段強制終止、重新開機、約 600 MiB 資料卷的記憶體峰值、安裝器回退、較大上傳視窗）的結果：驗證結果待回歸測試更新。測試方法見 [testing.md](testing.md)。
