## 目前設計

使用使用者提供的正式 SVG，主題藍 `#6183FC`。最新要求是全白底，已移除頁面底圖與灰色外框；實際卡片仍保留20px 圓角。字型為 Poppins、Outfit、Noto Sans TC；Yellowtail 檔案供品牌支援但沒有強加裝飾字到管理表格。既有 Cockpit 圖示、警示色與終端機配色保留。

12 個原生頁面及獨立畫面參考頁已套用樣式。更新頁在前次視覺巡檢中仍處於 PackageKit 載入；歷史指標提示需要 PCP。未宣稱這兩項後端能力完成。

## 2026.11.12.2：實際服務管理

已部署「系統 → 服務管理」，登入管理帳號並取得管理員權限後，預設載入設定的應用擁有者，可切換本機系統。新頁使用原有全白品牌樣式；本輪沒有重新設計既有原生頁。

當次盤點為287個使用者服務，其中63個 Quadlet、28個本機自訂單元；54個容器中48個有 systemd 關聯。這是包含已停止單元的盤點，不能當成啟用應用數。服務支援搜尋、篩選、分頁、詳細資料、日誌及單一服務啟動／停止／重新啟動。6個沒有單元關聯的容器在新頁提供唯讀清單和原生 Podman 入口。

### 實際操作驗證

- 從 Cockpit 瀏覽器操作三個臨時單元：本機系統服務、一般使用者服務、使用者 Quadlet。
- 共11次真實啟停／重啟，逐次以 systemd 狀態、PID及日誌交叉確認；取消確認視窗沒有操作。Quadlet 停止後容器移除，服務仍在清單且可再啟動。
- 23項服務操作、權限及版面檢查通過；桌面1440／1024與手機390／360px沒有文件橫向溢出，沒有頁面 JavaScript 例外。
- 部署最後版本後重新登入，7項讀取檢查通過：未授權資料隔離、預設擁有者、系統範圍、正式容器與單元對應、桌面／手機版面、原生頁手動選擁有者。
- 測試單元、容器和臨時系統單元已移除。Home Assistant、EMQX、n8n、Nextcloud、Odoo、LiteLLM、Hermes、Omnigent、OpenDesign、code-server、Headscale、Cloudflare Tunnel 的主單元仍為 active。本輪未對這些正式應用執行停機或完整業務驗收。

實測發現並修正：未命名 systemd 模板導致批次清單截斷、root 查到錯誤使用者日誌、stop 指令返回0但單元處於 failed 時誤報成功。這些已有回歸測試。

原生 cockpit-podman124 的首次載入仍可能重設擁有者或顯示空清單，並非所有容器消失。手動將 Owner 切到 All 再選回應用擁有者可顯示容器（先前紀錄誤寫為 Show，此處更正），已實測；此版本未修補上游載入時序，已在頁面與 [services.md](services.md) 說明。日常跨使用者 Quadlet 管理由新頁直接完成。

21項 Python 測試、8項服務前端瀏覽器測試及6項圖集檢查通過。實機 install → verify → install 校驗65個受管理檔案，重複安裝 changed=0；root helper為0755、擁有者設定為0600，無新增免密授權。摘要見 [service-validation-2026-11-12.json](service-validation-2026-11-12.json)。本輪仍未驗收另一台設備的全新安裝，也未實作應用備份還原中心。


## 2026.11.12.3：原生容器可見性、服務詳情與版面

本輪已修補原生 cockpit-podman124。修補前，管理員登入與 All 並不會自動開啟已設定應用帳號的 Podman 連線；首次 UID 導覽與舊連線清理也有時序問題。因此「沒有容器」並不能代表主機沒有部署。修補後，All 自動載入設定帳號，提升權限後會重新讀取設定。版本閘確保不以124版 bundle 覆蓋未驗證的新版本。

服務管理維持直接查詢設定帳號與本機系統。本輪瀏覽器讀到287個使用者單元、54個容器；詳情新增 PID、記憶體、累計 CPU、工作數、啟動時間、重啟規則、相依及執行結果，並實際讀取 EMQX 的單元詳情及日誌。

### 版面與最新登入要求

- 側欄左右裁切原因是向外畫出的鍵盤焦點框被捲動容器截掉，已改為向內繪製。巡檢也發現表頭、手機底部導覽及圖集連結有相同問題，已一併處理。
- 桌面登入卡片寬460px → 345px（75%），實測高度約75.2%；Logo 寬232px → 約255.2px（110%）。手機保留可操作的卡片寬度，Logo 也放大10%。
- 14個頁面 × 1440／1024／768／390px，共56組文件寬度與可見焦點框檢查：未測到橫向溢出或焦點裁切，沒有未捕捉的頁面 JavaScript 例外。這不是每一個欄位的業務驗收。

### 實際操作與回歸

- 原生頁從既有 Alpine 映像建立獨立容器，使用應用擁有者、64MiB記憶體限制，沒有綁定連接埠或資料卷。
- 從日誌終端的實際輸出確認測試訊息；操作停止、啟動、重新啟動、停止、刪除，並以 Podman 事件的 create／start／restart／died／remove 交叉確認。測試容器已清除。
- 12項既有應用主單元維持 active；沒有對正式應用執行啟停或升版。
- 從來源封存、patch及lockfile完整重建 bundle，與部署產物一致。22項 Python、4項擁有者事件、9項服務前端及6項圖集測試通過。89個受管理檔案 verify 通過，重複 install changed=0。

### 原始斷線的界線

使用者原始截圖的「管理範圍載入失敗／與主機連線已中斷」在本輪新工作階段未自然重現。重新登入、頁內提升權限、側欄導覽與重複切換均能載入資料，沒有證據可把原始錯誤直接歸因於 TLS 或主機停機。新增的「重新連線」會重新載入管理頁，斷線情境已用 Cockpit API fixture 驗證，且不重送服務啟停操作；不能據此宣稱原始斷線根因已完全確認。

原生終端及容器日誌仍有 CSP inline-style 警告，原生終端另有 FormSelect 無標籤警告；它們與本輪修正的擁有者載入、焦點框問題不同。未放寬預設 CSP；沒有宣稱瀏覽器控制台完全無警告。

數值摘要見 [management-validation-2026-11-12.json](management-validation-2026-11-12.json)。備份還原中心、GitHub應用商店及完整跨設備重建仍是後續功能。


## 2026.11.12.4：登入頁連續 RWD

修正上一版以 `zoom:.75` 縮小桌面卡片造成的斷點錯誤：767px視窗的卡片為460px，768px視窗反而只有345px；桌面輸入框也被縮成36px高。僅測桌面與手機兩端不足以發現此問題。

改為單一流動布局：卡片最大21.5625rem（標準字級為345px），小螢幕保留左右留白後縮寬；高度隨內容決定。Logo在同一欄位內等比例調整，標準字級最大約255.2px；不再以600／768px切換獨立的登入尺寸。輸入框與密碼按鈕維持48px高度，輸入文字16px，卡片20px圓角。字級改用rem，保留使用者放大文字的能力。頁尾原生nowrap造成長主機名稱溢出，也已修成可換行。

實際部署後檢查320／360／390／600／601／767／768／769／1024／1440px；卡片寬度不再隨視窗變窄而變大。另完成50個場景：一般及高像素密度（DPR1／2）、11種視窗尺寸下的收合／展開登入選項、320與720px下的200%文字，以及長錯誤訊息／密碼顯示切換。沒有文件橫向溢出、操作區超出卡片或未捕捉的頁面例外；橫放及短視窗可捲到登入按鈕。

720×450 CSS視窗涵蓋1440×900視窗在200%縮放時的有效排版寬高；沒有把DPR測試當成真實瀏覽器縮放或實體手機驗收。此次使用Chromium，未另行宣稱Safari／Firefox驗收。其他管理頁的全站巡檢結果維持上節所載，本輪CSS修改限於登入頁。

已部署並校驗89個受管理檔案；實機登入與服務管理導覽也通過。沒有重啟應用服務。詳細數值見 [login-rwd-validation-2026-11-12.json](login-rwd-validation-2026-11-12.json)。
