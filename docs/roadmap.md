# 尚待實作的產品功能

目前交付的是品牌化 Cockpit、原生管理頁、跨使用者的服務管理、Podman 應用「備份與還原」第一階段及部署來源。狀態、日誌、單一服務的啟動／停止／重新啟動已實作。

## 備份與還原：第一階段

客戶所需的流程已實作：建立備份或上傳備份檔 → 顯示應用、備份時間與相容性 → 檢查空間與完整性 → 確認還原 → 背景顯示進度與結果。使用方式見 [backup.md](backup.md)。

原先建議的四項驗收範圍，第一階段的做法：

1. **服務備份規格**：每個應用由受信任的目錄項目定義（[app-catalog.md](backup/app-catalog.md)），`quadlet-postgres` 轉接器以暫停寫入服務加上 `pg_dump` 取得一致的資料，不打包運行中的資料庫目錄。
2. **還原前檢查與保護**：完整解密並逐項核對備份檔、預檢版本、映像、空間與必要項目；原位還原先建立並驗證還原前備份，失敗時自動回復。
3. **可靠工作執行器**：systemd 背景作業、獨占鎖、去重、可在安全階段取消；瀏覽器關閉後作業繼續，中斷的作業會被標示且不自動重做。
4. **跨設備演練**：已在兩台隔離的實驗室設備完成（同一台主機上的獨立容器，各自擁有儲存、主機名稱、machine-id 與不同的應用擁有者 UID），以示範應用驗證匯入、全新部署、服務健康、應用機密與資料一致性及失敗回復。尚未在兩台實體設備演練。

2026-11-13 最終回歸全部通過（單元 471 項、頁面 fixture 30 項、CLI 端到端 126 項、頁面端到端 29 項、強化測試 554 項、作業紀錄競態探測 22 項），摘要見 [current-state.md](current-state.md)。

## 備份與還原：尚未涵蓋

- **正式應用接入**：每個應用都需要經審查的目錄項目與實驗室演練；目錄項目由應用套件安裝的發佈方式尚未建立。盤點、所需擴充與建議順序見 [production-onboarding.md](backup/production-onboarding.md)。
- **更多資料形態**：主機資料夾掛載、PostgreSQL 整個叢集（含角色）、資料庫資料放在主機資料夾、需要登入的應用改以 SQL 核對資料。
- **排程、保留策略、NAS 與雲端目的地**：第一階段明確不包含。
- **大型備份**：多 GB 備份與超過 8 GiB 的單一項目尚未實測。瀏覽器上傳已改為 512 KiB 分段、4 MiB 確認視窗，實驗室上傳 142 MB 的中位數為 12.8 MB/s（舊設定 6.7 MB/s），多 GB 檔案仍要數分鐘以上；中斷後續傳尚未實作。
- **驗證作業檢查備份內的 tar**：目前「驗證」只檢查外層封存，資料卷與映像封存的內部內容要到還原作業的相容性檢查才檢查，因此內部被改造的備份也會顯示「已驗證」。可考慮讓驗證作業做同樣的檢查。
- **全新部署被強制終止後的映像名稱**：復原會移除部署，但不會把作業載入映像時移走的既有映像名稱改回（只有作業自己執行的自動回復會改回）。
- **金鑰管理**：目前不能輪替設備金鑰，也不能從頁面移除匯入的金鑰。
- **其他範圍**：root（系統層級）Quadlet 應用、多節點應用、整機或裸機還原、不同 CPU 架構之間的還原、兩台實體設備之間的還原演練、沒有 PostgreSQL 的應用。

客戶自行線上升級不是目前第一階段要求。Cockpit package 機制可承載獨立頁面，但本身不提供 HA Supervisor 式的服務生命週期管理。
