# 維護與回退

## 更新來源

```bash
git pull --ff-only origin main
sudo python3 scripts/manage.py plan
sudo python3 scripts/manage.py install
sudo python3 scripts/manage.py verify
git rev-parse HEAD
dpkg-query -W cockpit-bridge cockpit-podman
```

出貨時記錄 commit、`VERSION`、實際套件版本及安裝輸出的 `backup_id`。安裝腳本沒有背景更新工作。要固定來源可先 `git checkout <已驗證的 commit>` 再執行安裝。

更新或回退前，先確認「備份與還原」沒有進行中的作業（見 [deployment.md](deployment.md)）；安裝器不會自行檢查。

驗證會比對已管理檔案的 SHA-256。若顯示 `drift`，先查看是上游升級或人工修改，再決定重新安裝。它只檢查檔案內容，不是服務健康、權限或完整安全稽核。

## 回退一次介面安裝

```bash
sudo python3 scripts/manage.py rollback <安裝輸出的 backup_id>
```

程式先檢查所有現有檔案與備份雜湊，再還原該次交易的原檔與權限；只刪除該交易新增的檔案，不遞迴刪除整個目錄。備份保留供追查。若檔案已被後續安裝、APT 升級或人工修改，回退會拒絕覆蓋。多次安裝應由最近一次向前回退。

安裝中捕捉到的寫入失敗會立即還原已寫入檔案；遇斷電等未能捕捉的中斷，可使用狀態為 `prepared` 的交易回退。磁碟故障仍可能使恢復失敗，需要依設備復原流程處理。

**這是管理介面、helper與設定檔回退，不是應用、資料庫、整機或客戶備份檔的還原。** 應用資料請用「備份與還原」頁還原，見 [backup.md](backup.md)。回退不安裝／解除安裝 APT 套件、不還原 Cockpit 密碼、TLS 或防火牆，也不撤銷操作者先前執行的服務啟停；不會碰備份檔、加密金鑰與作業紀錄。第一次安裝回退後沒有狀態檔是正常的；若回退到先前來源版本，verify 會檢查先前版本。

## 常見問題

| 現象 | 檢查方式 |
| --- | --- |
| 新頁或新增圖片 404 | 登出再登入，重新建立 Cockpit bridge 的套件檔案清單；再強制重新整理 |
| 顏色仍是舊版 | 瀏覽器可能快取 static/branding.css；重新整理、確認 verify 與實際載入的 CSS |
| 只有某個頁面未套用品牌 | 檢查原生 HTML 是否被 APT 覆寫，重跑 plan／install；檢查新版類別 |
| Podman 顯示零容器 | 確認登入者、管理權限、擁有者選單及對應 rootless 儲存區 |
| 圖集顯示待擷取 | 正常：新設備未匯入截圖；依 testing.md 擷取再匯入 |
| 手機圖截斷 | 使用 capture 的完整總覽輸出，不用固定高度截取 iframe；圖集可捲動原圖 |
| 更新頁一直載入 | 檢查 PackageKit/APT；此品牌來源沒有解決後端套件來源問題 |
| 缺歷史指標 | 另外配置 PCP／cockpit-pcp；這次沒有將其納入 bootstrap |
| 開不了 9090 | 檢查 cockpit.socket、路由、防火牆及 TLS；品牌檔案不控制連接埠 |
| 備份頁顯示「找不到備份管理程式」 | 備份元件未安裝或不完整；執行 plan／install／verify |
| 備份頁顯示「尚未設定可備份的應用」 | 正常：尚未安裝任何應用目錄項目，見 [app-catalog.md](backup/app-catalog.md) |
| 備份頁出現「備份設定提示」 | 有目錄項目被略過；依提示修正檔案權限或格式 |
| 應用狀態「異常」，提示使用者服務管理器未啟動 | 為應用擁有者啟用 linger：`sudo loginctl enable-linger <應用擁有者>` |
| 應用狀態「異常」，提示服務已啟動但健康檢查未通過或沒有回應 | 服務在執行但應用不健康；到「服務管理」查看該應用的服務日誌。異常的應用不能建立備份 |
| 應用狀態「異常」，提示服務已被暫時停用 | 先前的還原沒有完成；依「處理中斷的作業」用還原前備份再次還原，不要手動 `unmask` |
| 還原被拒絕：資料庫執行個體中還有應用設定未宣告的資料庫 | 原位還原會重建整個資料庫資料卷，那些資料庫會遺失，所以沒有做任何變更。先把它們移到其他執行個體（或確認不需要後刪除）再還原；應用本身需要多個資料庫時，目前的備份方式不適用（見 [production-onboarding.md](backup/production-onboarding.md)） |
| 還原被拒絕：備份中的資料卷或容器映像含有不安全或不支援的內容 | 設備沒有任何變更；不要再用這份備份，改用其他備份，並保留檔案回報工程人員 |
| 備份失敗：資料卷含有還原時無法匯入的內容 | 依訊息處理該資料卷中的項目（例如指向資料卷外的相對符號連結、擁有者不在應用擁有者的 UID 對應範圍內）；應用已恢復執行 |
| 錯誤 `internal-error`，訊息提到 age 或 zstd | 安裝 `age`、`zstd`（`bootstrap-ubuntu.sh --apply` 會安裝） |

不要為了讓圖集出現而重新啟動所有容器；圖集只是 Cockpit 套件。此安裝器不主動中斷 Cockpit 或既有應用服務。

## 備份與還原：資料、清理與中斷處理

操作說明與錯誤代碼見 [backup.md](backup.md)。

### 資料與金鑰位置

| 路徑 | 內容 | 說明 |
| --- | --- | --- |
| `/var/lib/woowtech-backup/archives/<備份 ID>.woowbackup` | 加密的備份檔 | 整個 `/var/lib/woowtech-backup/` 只有 root 可存取（0700） |
| `/var/lib/woowtech-backup/archives/<備份 ID>.json` | 列表索引：類型、應用、大小、SHA-256、驗證結果 | 從頁面刪除時與備份檔一起刪除 |
| `/var/lib/woowtech-backup/uploads/` | 上傳中的檔案 | 取消上傳時刪除；未完成的上傳超過 24 小時，會在下一次開始上傳時清除 |
| `/var/lib/woowtech-backup/staging/<作業 ID>/` | 作業期間的**明文**暫存：資料庫匯出、資料卷內容、應用機密 | 作業結束或被判定中斷時刪除 |
| `/var/lib/woowtech-backup/jobs/<作業 ID>.json`、`.log`、`.lock`、`.cancel` | 作業紀錄、日誌、紀錄鎖（空檔案）與尚未處理的取消要求，不含金鑰與應用機密內容 | 自動保留最近 200 筆已結束的作業（含日誌），更舊的會被刪除；進行中的作業、仍需復原處理的作業，以及還原前備份仍被釘選的失敗或中斷還原，一律保留。頁面顯示最近 50 筆 |
| `/var/lib/woowtech-backup/requests.json` | 防止重複送出的要求紀錄 | 超過 24 小時的項目自動丟棄 |
| `/etc/woowtech-cockpit/backup/keys/device-<金鑰 ID>.key` | 設備金鑰（0600，資料夾 0700） | **不要刪除**；遺失後只能用緊急金鑰還原以它加密的備份 |
| `/etc/woowtech-cockpit/backup/keys/imported-<金鑰 ID>.key` | 匯入的其他設備金鑰 | 頁面目前不能移除 |
| `/etc/woowtech-cockpit/backup/keys/keys.json` | 金鑰中繼資料：建立時間、是否已確認保存緊急金鑰 | 損毀只會失去中繼資料，金鑰檔才是依據 |
| `/run/woowtech-backup/` | 作業鎖（`engine.lock`、`jobs.lock`、`index.lock`）與單次作業的暫時金鑰檔 | 記憶體檔案系統，重新開機即清空 |
| `/etc/woowtech-cockpit/backup/apps/` | 受信任應用目錄 | 見 [app-catalog.md](backup/app-catalog.md) |
| `/usr/local/share/woowtech-cockpit-backup/catalog/` | 全新部署用的範本 | 同上 |

備份與應用資料通常在同一顆磁碟；重要的備份請下載保存到其他位置。設備重新安裝前，確認緊急金鑰已另外保存，並下載需要保留的備份。

### 清理

- 從頁面刪除不需要的手動與上傳備份；需要保留的先下載。手動與上傳的備份不會自動刪除。
- 「還原前自動備份」（列表類型「還原前備份」）每個應用保留最近 3 份，較舊的會在之後的原位還原成功後自動刪除；失敗或中斷的還原仍需要的還原前備份不會被自動刪除。不需要時可從頁面手動刪除，但還原作業進行中時不能刪除。
- 不要直接在檔案系統刪除或搬動 `archives/` 內的檔案，索引與備份檔會不一致；請用頁面刪除。
- 暫存資料夾在作業結束時刪除；被強制終止的作業在判定中斷時刪除。頁面讀取狀態或活動紀錄時，也會清除不屬於進行中作業的暫存資料夾。
- 作業紀錄每次讀取狀態、作業或活動紀錄、刪除備份或開始新作業時自動整理：保留最近 200 筆已結束的作業與其日誌，更舊的刪除；進行中的作業、仍需復原處理的作業，以及還原前備份仍被釘選的失敗或中斷還原不會被刪除。紀錄已不存在的日誌、鎖或取消要求檔，超過一小時後清除。被刪除的作業，用同一個請求識別碼再次送出時會建立新作業。實驗室在兩台設備各連續執行 110 個作業後確認：已結束的紀錄、日誌與鎖檔各保留 200 個。

### 處理中斷的作業

作業程序被強制終止、斷電或重新開機時，紀錄會停在「執行中」。

1. **開啟或重新整理「備份與還原」頁。** 頁面讀取狀態、作業或活動紀錄時，系統會檢查紀錄為「等待開始」或「執行中」、但 systemd 單元已不在執行且引擎鎖已釋放的作業（剛排入的作業有 2 分鐘緩衝），把它標為「已中斷」，清除它的暫存資料與暫時金鑰，並重新啟動備份時被暫停、尚未恢復的寫入服務。判定時以作業最後寫下的紀錄為準：檢查期間剛好正常結束的作業保留自己的結果，不會被誤判為已中斷，也不會被重新啟動服務或清除剛完成的全新部署；有作業正在執行時不做任何判定。**系統不會自動重做作業。**
2. **依作業結果頁的「接下來怎麼做」處理：**
   - 備份：到「總覽」確認應用為「執行中」，再重新建立備份。若有服務無法自動重新啟動，結果訊息會列出服務名稱，請到「服務管理」選擇應用擁有者後啟動。
   - 原位還原：結果頁列出還原前備份時，按「使用還原前備份還原」把應用回到還原開始前的狀態。還原中被暫時停用（mask）的服務在這之前會保持停用（重新開機後也不會啟動），「總覽」把應用顯示為「異常」並說明原因；不要手動 `unmask` 後啟動，以免應用在只還原一半的資料上執行。應用異常時通常無法再建立新的還原前備份，還原的又是還原前自動備份，所以會直接還原（失敗時無法自動回復）。沒有還原前備份，代表中斷發生在建立它之前，應用資料應未被變更。
   - 全新部署：判定中斷時，系統會清除未完成的部署（Quadlet 檔、服務、資料卷、應用機密、設定檔與網路），結果訊息說明是否完整清除；完成後可再次還原同一份備份，未能完整清除時依訊息列出的項目人工處理。資料匯入已完成、服務已解除停用或正在執行的部署不會被自動移除，訊息會要求人工確認。被終止的作業載入映像時移走的既有映像名稱不會改回（只有作業自己執行的自動回復會改回）；需要時以應用擁有者身分用 `podman tag` 指回原本的映像。實驗室實測：在「啟動應用」階段強制終止全新部署，復原移除整個部署，同一帳號的其他資料卷、應用機密、設定檔、網路與映像名稱都沒有變，之後再次全新部署成功。
   - 驗證：重新執行驗證。
3. **主機端檢查**（需要時，以 root 執行）：
   - `systemctl list-units 'woowtech-backup-*'`：確認沒有作業單元仍在執行。
   - `journalctl -u woowtech-backup-<作業 ID>.service`：該作業程序的系統日誌；未預期錯誤的細節只寫在這裡，頁面只顯示一般訊息。
   - 應用服務：在「服務管理」選擇應用擁有者查看狀態與日誌。
4. **還原前備份也無法還原時**：不要刪除該備份；記錄作業 ID、錯誤訊息與日誌，交由工程人員處理。

不要用 `systemctl stop` 或 `kill` 中止作業；需要停止時使用頁面的「取消作業」，它只在安全的階段可用。實驗室已驗證（2026-11-13 最終回歸）：

- 強制終止原位還原後，以還原前備份恢復，資料與中斷前完全相同。
- 還原進入「啟動應用」階段時重新啟動設備：作業在關機時自己結束為「已中斷」並記下還原前備份 ID，沒有嘗試自動回復；開機後資料庫服務執行、應用服務保持停用，總覽顯示「異常」；用還原前備份還原後，資料與還原前完全相同。
- 備份在各階段被強制終止：復原流程重新啟動被暫停的寫入服務，清除暫存，沒有留下未列出的備份檔，下一次備份成功。

極少數情況下，備份作業在備份檔移入保存位置之後、寫入索引之前被終止。這個檔案放置超過一小時後，下一個作業開始時會找到它並列為「上傳」類型的備份，可檢視內容後決定保留或刪除。

### 移除備份套件

`--no-backup` 不是解除安裝，只是不再安裝與追蹤。要移除頁面、引擎與 helper，回退加入它們的那次安裝交易（依上方回退規則，由最近一次往前回退）。安裝器不會刪除 `/var/lib/woowtech-backup/` 與 `/etc/woowtech-cockpit/backup/keys/`，也不會刪除手動放置的目錄項目與範本；是否刪除由設備管理者決定，刪除金鑰前務必確認緊急金鑰已另外保存。

實驗室演練（dev-a，2026-11-13）：`plan`／`install`／`verify` → 回退最新一次交易（`verify` 依回退後的狀態通過，舊版引擎仍可使用）→ 繼續往前回退 3 次交易，直到 helper、頁面與目錄設定都不在 → 重新安裝 → `verify`。每一步比對 `/var/lib/woowtech-backup/`（716 個檔案）與金鑰資料夾的內容，全程沒有變化；應用在沒有備份套件時持續執行；重新安裝後同一把設備金鑰仍能驗證既有備份。
